# One published corpus for native numerical evidence

The user's 28 October authorization permits adapting M1 data structures and module
interfaces for integration. Native numerical candidates now use the existing M1
publication build, graph/retrieval preparation, final commit and publication head.
This replaces the earlier need to keep numerical output in a separate unpublished
adapter. Source evidence, actual reviews and amendment history remain immutable.

## Build and publish

Use migration 21 and the existing native API startup with an explicit
`--numerical-runtime-file` and the pinned local publication/embedding prerequisites.
Use actual administrator-reviewed source/context/candidate/acceptance IDs. Obtain
the current published corpus ID before creating the next publication request:

```text
POST /v1/admin/publication/builds
{
  "idempotency_key": "<canonical request ID>",
  "parent_corpus_version_id": "<current published ID, or null if none>",
  "selections": [{
    "candidate_run_id": "<native bound gate ID>",
    "candidate_id": "<saved numerical candidate ID>",
    "review_id": "<explicit ACCEPT decision ID>"
  }],
  "lineages": [],
  "effects": []
}

POST /v1/admin/publication/builds/{corpus_id}/publish
```

These are placeholders, not approvals. Existing legacy selections use their
original run/candidate/review IDs. Native and legacy selections can share a build;
ambiguous producer identities fail. The application freshly verifies all source,
parse, evidence, approval, context and acceptance dependencies at build and final
commit. The source runtime must be explicitly configured for native publication.
Missing, rejected, stale or unsupported inputs cannot publish. A build alone is
unavailable to public readers.

The native snapshot is explicitly `NATIVE_NUMERICAL`. Its observation schema is
`native-numerical-observation-1`; it retains the complete word/cell/geometry proof,
exact quantity and its own native acceptance run. No legacy ValidationRun or
combined source quotation is fabricated. Public supports retain all distinct
native words, with a 1,024-word bound. Decimal values remain strings on the wire
and NUMERIC in authoritative PostgreSQL storage.
The original currency token (`₹`, `Rs.`, `INR` or `USD`) remains separate from the
normalized currency; retained source definitions still determine its meaning.

## Atomic authority and history

Migration 21 adds append-only `native_publication_audits` and adapts the common
observation/commit guards. Native audit snapshots must exactly match stored
candidate, preparation, acceptance, checks, quantity, proof and source metadata.
The common `publication_observations` table holds authoritative native observations
alongside existing observations. A removed legacy-only candidate foreign key is
replaced by producer-specific snapshot validation and the native candidate/audit
foreign keys. It is not an unguarded acceptance path.

After verified graph/retrieval preparation, the audit, observation, published
state and common head commit together or roll back together. Exact published
replays preserve the original outcome. A new request cannot duplicate an existing
observation. Native parents can advance with additional legacy content without
rewriting or implicitly superseding the earlier numerical observation. The same
explicit lineage/effect engine determines active/as-of status for both sources;
missing amendment support or effective dates still cannot be invented.

Entity evidence loading now supports both sealed parser sidecar formats. Frozen
native catalog labels/metrics come from the audited gate input, never the current
global registry. Public evidence and original-PDF reads retain exact published
filing/parse/source membership. The original legacy observation bytes remain
readable; preserving history does not prevent adapting current interfaces.

## Module consumers and verification

M1 facts/evidence, M2 comparison, M3 context and M4 company selection share the
committed corpus. Shared schemas/types are regenerated by the existing export
scripts. Browser checks verify complete native support/word/cell/page membership;
incomplete numerical learning context is rejected. The administrator accepts
the explicit native or legacy review snapshot. The numerical publisher initially
uses existing literal-support retrieval chunks; grouped reconstructed draft
chunks are not silently installed as original quotations.

The shared source viewer starts PDF work only for a surviving React setup and
destroys it on unmount. New source bytes clear previous render/error state. This
avoids duplicate development workers while keeping source hashes, exact original
page rendering and geometry checks intact.
Browser tests wait up to 15 seconds for asynchronous PDF readiness, then retain
their original canvas/highlight/hash assertions. Traces showed worker loading
alone approaching the previous five-second default; no rendering SLA is claimed.

`native.fixture.json` and `native-context.fixture.json` are labelled authored
HTTP fixtures captured from owned PostgreSQL engineering tests. They contain
fictional sources/decisions and no credentials or PDFs. Positive tests do not
approve real filings, glossary content, market prices or research gold.

disclosed attempts. CI's infrastructure budget is now 60 minutes while retaining
